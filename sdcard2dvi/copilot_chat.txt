## 診断結果

**症状**：画面がほぼ白一色＋ノイズ。これは「フレームバッファに画像データが一度も書き込まれていない」状態で DDR3 を読み出し続けている典型的な兆候です（未初期化の DDR3 データをそのまま表示 → 白＋ノイズ）。

**根本原因**：`sd_reader.sv` の **R1 応答受信ロジックのバグ** です。

SPI モードでは、コマンドに対する R1 応答の「スタートビット（MISO=0）」は、実は **R1 バイトの最上位ビット（bit7）そのもの**です。しかし元のコードはスタートビットを検出しただけで破棄し（`rx_sr <= 0`、`rx_bit_cnt <= 0`）、その後 8bit をシフトしていました。このため受信値が 1bit 左シフトされ、`R1 << 1 | 1` の値になってしまいます。

- 本来 CMD0 の応答 `0x01` のはずが **`0x03` として受信**
- `ST_WAIT_CMD0` は `rx_byte == 0x01` を待つため永遠に `ST_SEND_CMD0` に戻り、初期化が完了しない
- → `init_done` が立たず、`block_cnt` の読み出しが始まらず、フレームバッファ未書き込み

## 証拠（GAO キャプチャ解析）

`sdcard2dvi_5_core0.csv` を解析したところ：
- SD 状態機械は `ST_SEND_CMD0(1)`/`ST_WAIT_CMD0(2)` に留まり、`init_done`（state 9 以降）に到達しない
- 受信バイトは `0x03`（期待値 `0x01`）のみ
- `read_req` は発行されない

## 修正内容

`sd_reader.sv` の R1 受信部で、スタートビットを破棄せず `rx_sr[0]` に取り込み、`rx_bit_cnt` を 1 から開始するよう修正しました。これで `{rx_sr[6:0], sd_dat}` のシフトにより 8bit の R1 が正しく組み立てられます。

```systemverilog
// 修正前: スタートビット破棄 → R1 が左シフトして誤受信
rx_sr      <= 8'd0;
rx_bit_cnt <= 3'd0;

// 修正後: スタートビット = R1 bit7 として取り込む
rx_sr      <= {7'b0, sd_dat};
rx_bit_cnt <= 3'd1;
```

## 診断結果

**症状**：画面がほぼ白一色＋ノイズ。これは「フレームバッファに画像データが一度も書き込まれていない」状態で DDR3 を読み出し続けている典型的な兆候です（未初期化の DDR3 データをそのまま表示 → 白＋ノイズ）。

**根本原因**：`sd_reader.sv` の **R1 応答受信ロジックのバグ** です。

SPI モードでは、コマンドに対する R1 応答の「スタートビット（MISO=0）」は、実は **R1 バイトの最上位ビット（bit7）そのもの**です。しかし元のコードはスタートビットを検出しただけで破棄し（`rx_sr <= 0`、`rx_bit_cnt <= 0`）、その後 8bit をシフトしていました。このため受信値が 1bit 左シフトされ、`R1 << 1 | 1` の値になってしまいます。

- 本来 CMD0 の応答 `0x01` のはずが **`0x03` として受信**
- `ST_WAIT_CMD0` は `rx_byte == 0x01` を待つため永遠に `ST_SEND_CMD0` に戻り、初期化が完了しない
- → `init_done` が立たず、`block_cnt` の読み出しが始まらず、フレームバッファ未書き込み

## 証拠（GAO キャプチャ解析）

`sdcard2dvi_5_core0.csv` を解析したところ：
- SD 状態機械は `ST_SEND_CMD0(1)`/`ST_WAIT_CMD0(2)` に留まり、`init_done`（state 9 以降）に到達しない
- 受信バイトは `0x03`（期待値 `0x01`）のみ
- `read_req` は発行されない

## 修正内容

`sd_reader.sv` の R1 受信部で、スタートビットを破棄せず `rx_sr[0]` に取り込み、`rx_bit_cnt` を 1 から開始するよう修正しました。これで `{rx_sr[6:0], sd_dat}` のシフトにより 8bit の R1 が正しく組み立てられます。

```systemverilog
// 修正前: スタートビット破棄 → R1 が左シフトして誤受信
rx_sr      <= 8'd0;
rx_bit_cnt <= 3'd0;

// 修正後: スタートビット = R1 bit7 として取り込む
rx_sr      <= {7'b0, sd_dat};
rx_bit_cnt <= 3'd1;
```

## 診断と修正

**原因**：BMP データは各行「左→右」のラスタ順で格納されており、`bmp_parser` も `frame_writer` も到着順のまま VFB に書き込んでいます。VFB の読み出し側（`vout`）はアドレスをラスタ順に自動生成するため外部から制御できず、水平方向の反転は**書き込み側でしか行えません**。これが左右反転の正体です。

**修正内容**（`frame_writer.sv`）：水平反転用の**ピンポン・ラインバッファ**を実装しました。

- 1 行分（1280 ピクセル）を `lb0`/`lb1` の 2 本のラインバッファに交互に書き込み
- 1 行埋まったら、そのバッファを**逆順（右→左）**に吐き出して VFB へ出力
- 入力（3 クロックに 1 ピクセルのバースト）と出力（1 クロック 1 ピクセル）を分離し、読出しと書込みが競合しないよう 2 本を交互使用
