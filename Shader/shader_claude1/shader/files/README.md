# terrain_raymarch_sv — GLSLレイマーチング山岳シェーダーのSystemVerilog移植

元のShadertoy風GLSL (fbmノイズ地形 + ソフトシャドウ + フォグ) を、
1ピクセルずつ計算する固定小数点FSMとしてSystemVerilogに移植したものです。

**固定小数点フォーマット: Q8.16 (24bit signed, 小数部16bit)**
表現範囲は約 **-128.0 〜 +127.9999847**、精度は約 2^-16 (≒0.0000153)。
(以前のQ12.20版は約±2048の範囲でしたが、リソース削減のためQ8.16に縮小しました)

## ファイル構成 (Vivado/Quartus/GOWIN EDAへの追加順)

1. `rm_pkg.sv` (+ `sin_lut.svh`, `exp_lut.svh` を `include`)
   Q8.16固定小数点の共通ユーティリティ。sin/exp はcase文によるROM関数
   (ILI9341プロジェクトと同じ「ROM-via-case」方式、`initial`ブロック不使用)。
2. `map_core.sv` — GLSLの `map(vec3 pos)` (fbm地形高さ関数) を1オクターブ/クロックで計算するFSM。
3. `isqrt.sv` — `normalize()` とガンマ補正 `sqrt(col)` 用の固定小数点sqrt FSM (桁ごと復元法)。
4. `fixed_div.sv` — `calcShadow` の `h*164.0/t` や `normalize` の逆数計算用の符号付き除算FSM。
5. `pixel_render.sv` — `mainImage()` 本体。
6. `frame_scan.sv` — 画面全体をラスタスキャンしながら `pixel_render` を駆動するトップモジュール。
   `pixel_valid` / `pixel_col` / `pixel_row` / `pixel_rgb565` を1ピクセルずつ出力するので、
   既存のST7789V/ILI9341 SPIドライバの書き込みシーケンスにそのまま接続できます。

## Q8.16化にあたって発見・修正した3つのオーバーフロー問題

Q12.20(整数部±2048)からQ8.16(整数部±128)へ縮小したことで、単純に定数を
再計算するだけでは済まない箇所が3つありました。いずれも **シミュレーションで
実際に誤った出力(異常に暗い/負の色)が出ることを確認した上で** 修正しています。

1. **sinのLUTインデックス計算**: `1024/(2π) ≈ 163.97` という定数自体が
   Q8.16(最大約128)に収まらない。→ 角度を明示的に0〜2πへ正規化してから
   定数倍する方式をやめ、「2の補数表現の性質上、`n_frac`(=angle/2π)の
   下位16ビットがそのまま小数部を表す」ことを利用し、単なるビット切り出し
   (`n_frac[FRAC-1 -: SIN_BITS]`)でLUTインデックスを得る方式に変更。
   定数を一切使わずに済み、Q8.16化と無関係にそもそも安全な実装になった。
2. **exp(-y)のLUTインデックス計算**: `(EXP_N-1)/EXP_Y_MAX=63.75` という
   定数自体はQ8.16に収まるが、`y(最大4.0)`との積の実数値(最大255程度)が
   収まらずfmul内でオーバーフローしていた。→ `fmul`(固定小数点同士の乗算)
   を使わず、「fixed_t × 整数(EXP_N-1)」という広い中間幅の乗算として計算し、
   `EXP_Y_MAX=4.0=2^2`であることを利用して単純な右シフトで割り算を済ませる
   方式に変更(`rm_pkg.sv`の`exp_neg_fx`)。
3. **calcShadowの `h*164.0/t`**: 定数164.0自体がQ8.16に収まらない
   (整数部最大127)ため、`fmax(h,0)*164`を「fixed_t × 整数164」の広い中間幅
   乗算+飽和(`sat_from_wide`)で計算するよう変更。
   さらに、**割り算の商そのもの**が128を超えるケース(除数tが小さいうちは
   商が数十〜200超になりうる)があり、`fixed_div`が商をそのまま下位24ビットへ
   切り詰めていたため符号が反転した巨大な負の値が発生し、シャドウが常に
   真っ黒になる不具合があった。→ `fixed_div`に商のオーバーフロー検出を追加し、
   範囲を超える場合は符号付き最大値(MAXVAL/MINVAL)へ飽和させるよう修正
   (GLSL側は`min(res, 巨大な値)`で自然に無害化されるが、固定小数点では
   その「巨大な値」自体が表現できないため、あらかじめ飽和させることで
   同じ効果を得ている)。

この3点は `map_core`(ビット完全一致検証済み)・`isqrt_fx`(28パターンで
完全一致)・`fixed_div`(オーバーフロー境界を含む30パターンで完全一致)の
単体シミュレーション、および `pixel_render` でのピクセル単位シミュレーション
(地形にヒットするレイの陰影計算過程をトレースし、シャドウ係数が1.0から
滑らかに0.0へ収束することを確認)によって検出・修正しています。

## 検証状況 (iverilogでのシミュレーション、Q8.16版)

- `map_core`: Pythonの固定小数点リファレンスモデルと5パターンで完全一致。
- `isqrt_fx`: 24パターンで完全一致。
- `fixed_div`: 通常ケースおよびオーバーフロー飽和ケースを含む30パターンで完全一致。
- `pixel_render`: 空を見上げるレイは手計算値と完全一致。地形にヒットするレイは
  シャドウ計算が正しく収束し、色出力(rgb565=3208)がQ12.20版(rgb565=3207)と
  ほぼ同一(最下位ビットの精度差のみ)になることを確認。
- `frame_scan`: 4x2解像度での全画面スキャンが正常完走。

実機(FPGA)での動作確認はまだ行っていません。

## Q8.16での主な制約・注意点

- **カメラのz座標 (`-iTime`)**: 表現範囲が±128に縮小したため、Q12.20版より
  はるかに短い時間でラップアラウンドします。`frame_scan`の
  `TIME_STEP_PER_FRAME`次第ですが、長時間のデモには`time_reg`の周期リセット
  や、この一箇所だけ広いビット幅を使うといった対策を検討してください。
- **mapのfbmループ内でのq(ノイズ座標)の増大**: `q`は1オクターブごとに
  約1.7倍(10オクターブで最大1.7^9≈97倍)に増大するため、カメラから
  ある程度離れた地点では`q`自体がQ8.16の範囲を超えてラップアラウンドします。
  これはノイズの「模様」が元のfloat版と厳密には一致しなくなることを意味し
  ますが、sin関数自体は(ビット切り出し方式のおかげで)どんな入力に対しても
  正しく周期的な値を返すため、見た目としては「境界のない手続き型ノイズ」が
  引き続き得られます。元のfloat版も無限精度ではないため、遠方では同様の
  性質(パターンの見た目の変化)を持ちます。
- 表現範囲そのものが±128と狭いため、シーンのスケール(カメラ高さ、地形の
  起伏など)を大きく変える場合は、他にも同様のオーバーフローが起こりうる
  点に注意してください。本移植では「定数として保持する値」と「乗算・除算の
  結果として現れる値」の両方をQ8.16の範囲でレビューしましたが、パラメータ
  (`NUM_OCTAVES`やシーン定数)を変更した場合は再チェックを推奨します。

## 性能に関する注意 (Q12.20版から変更なし)

1ピクセルあたり `map_core` 呼び出しが最悪ケースで約326回(march 256 + 法線 6 +
シャドウ 64)、`fixed_div` 呼び出しがシャドウループで最大64回。ビット幅が
32→24に縮小したことで乗算器・除算器のFPGAリソースはやや軽くなりますが、
`fixed_div`の反復回数(WIDTH+FRAC=40サイクル、旧52サイクルから若干短縮)を
含め、そのままでは320x240のリアルタイム表示速度には程遠い点は変わりません。
高速化の方向性(オクターブ数/マーチステップ数の削減、`map_core`の並列
インスタンス化、`cos_noise`のパイプライン化など)は引き続き有効です。
